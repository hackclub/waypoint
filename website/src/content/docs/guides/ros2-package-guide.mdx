Your ROS 2 package is one of the three things required for a Waypoint submission, alongside your PCB and chassis CAD. It is the source code that will run on the Raspberry Pi in your kit.

By the time you finish this guide, your repository should contain a package that:

- accepts standard `Twist` movement commands on `/cmd_vel`
- turns those commands into real motor-driver output for the shared Waypoint hardware
- publishes data from the required IMU on `/imu/data_raw`
- publishes open-loop dead reckoning because Waypoint kits do not include wheel encoders
- works with standard ROS keyboard teleop and includes a small autonomous routine you wrote
- has configuration and launch files that make the package understandable to someone else

Make your own code! Dont just copy my example. The pin assignments, package name, motor settings, IMU orientation, and autonomous behavior should come from your own design.

## What You Are Building

ROS 2 lets small programs called **nodes** exchange structured messages. For this package, keep the path simple:

| Node | Input | Output | Job |
| --- | --- | --- | --- |
| Motor driver | `/cmd_vel` (`Twist`) | your motor driver's real control signals | move the chassis |
| IMU | physical I2C readings | `/imu/data_raw` (`Imu`) | report acceleration and turn rate |
| Open-loop odometry | `/cmd_vel` | `/odom`, `/path`, and `odom -> base_link` | track the robot's commanded motion |
| Autonomous routine | its timing or state | `/cmd_vel` (`Twist`) | make the robot follow your short routine |

Teleop and autonomy both publish the same `Twist` message. That separation is the useful ROS idea here: the motor node handles the hardware once, while different nodes can request motion. The official [topics, services, and actions overview](https://docs.ros.org/en/jazzy/How-To-Guides/Topics-Services-Actions.html) explains the broader ROS 2 communication model.

<details>
  <summary>Why are the guides using ROS 2 Jazzy?</summary>
  The Waypoint guides target **ROS 2 Jazzy** on **Ubuntu 24.04**. ROS provides Jazzy binaries for Ubuntu 24.04 on both 64-bit x86 development computers and 64-bit ARM computers, and Ubuntu supports Ubuntu Server on the Raspberry Pi Zero 2 W. That gives the laptop and the Pi the same ROS release later. See [ROS 2 Jazzy platform support](https://docs.ros.org/en/jazzy/Installation/Alternatives/Ubuntu-Install-Binary.html) and [Ubuntu's Raspberry Pi support table](https://ubuntu.com/hardware/docs/boards/how-to/ubuntu_supported/raspberry-pi/).

## Learn From Real Code

Use examples to answer a specific question, then write the version that fits your robot:

- [ROS 2's official package guide](https://docs.ros.org/en/jazzy/How-To-Guides/Developing-a-ROS-2-Package.html) is the best reference for package structure, `package.xml`, `setup.py`, and Python executables.
- [ROS 2's Python publisher/subscriber tutorial](https://docs.ros.org/en/jazzy/Tutorials/Beginner-Client-Libraries/Writing-A-Simple-Py-Publisher-And-Subscriber.html) is the best starting point for `rclpy` node structure.
- [OrphBot's example package](https://github.com/SharKingStudios/orphbot-package) is a small example codebase to inspect to help you understand the sections here.
- [Terralift](https://github.com/SharKingStudios/Terralift) is a larger real robot. Its `drivetrain_node.py`, `imu_node.py`, and `open_loop_odom_node.py` show how the same ideas grow in a more complex project.

**Do not rename an example package and submit it.** *(I am checking...)* Follow a topic from publisher to subscriber and adapt the idea to your own hardware and behavior.

## Your Route

Work through these pages in order. Each page ends by pointing to the next piece of the same package.

1. [Create your workspace](/guides/ros2-package-guide/workspace/) and set up the package files.
2. [Build movement nodes](/guides/ros2-package-guide/driving/) for `/cmd_vel`, motors, and dead reckoning.
3. [Publish IMU data](/guides/ros2-package-guide/imu/) from the required sensor.
4. [Add teleop and autonomy](/guides/ros2-package-guide/autonomy/) through the same movement topic.
5. [Polish your package](/guides/ros2-package-guide/polish/) before submitting it.

For the installation commands, use [Set Up Ubuntu for ROS 2](/reference/set-up-ubuntu-for-ros/). Windows users do that in WSL Ubuntu 24.04; Linux users can use their terminal; macOS peeps use an Ubuntu 24.04 VM or remote Ubuntu computer.

## Words You Should Know

| Word | Meaning |
| --- | --- |
| Workspace | The folder that holds ROS 2 packages and is built by `colcon`. |
| Package | The code, metadata, configuration, and assets for one part of a ROS project. |
| Node | One running ROS program with a focused job. |
| Topic | A named stream of messages between nodes. |
| Parameter | A named setting supplied to a node, such as a GPIO pin or speed limit. |
| Launch file | A Python file that starts the nodes that run together. |

Start with [Creating your workspace](/guides/ros2-package-guide/workspace/).
